- 中英文采用省略主语的履历句式，直接写职责和行动；去掉“李征是一位”“Zheng is”“他”“He”的传记式介绍。
- 微软任职仍为 2012 年至今，当前团队明确为 Microsoft Teams。转组月份尚未确认，不把 Teams 任职起点写成 2012 年，也不根据博客日期猜测月份。职位沿用现有简历和 GitHub 的 Principal Software Engineering Manager。
- 去掉旧组织路径和未经确认的当前团队人数。移动产品经历标明为此前经历，压缩为少量事实，不再展开内部实现。

- 保留职级历程、阿里巴巴和微软亚洲研究院经历、两条学历、专利编号及四个社交链接。
- 简历不再使用会过时的“15 年”和“正在重塑自己”，改用明确的职业起点及当前工作方向。入口页原有年数差异仍作为独立编辑议题，不在本轮推算或改写。

## 实现与验证

两份简历 Markdown 同时供应 HTML、公开 Markdown 和 llms.txt。元数据摘要与正文一起更新，分享图姓名和职位未变。内容模型仅同步最后一节的新标题；原有 HTML 安全测试改用稳定的章节标题插入测试内容，避免依赖已删除的第三人称句子。社交链接去重测试改为匹配完整主页 URL，避免误改正文中新增的项目 URL。

新文案在原打印样式下仍占三页。打印样式收紧标题、段落和列表留白，使用完整页宽，并保持两段较短的早期经历不在列表中分页。中英文导出现在均为两页 A4，正文为 10pt。打印时隐藏跳转链接，使用系统静态字体，解决原可变字体在 PDFKit 提取文本时把姓名和项目名拆散的问题；屏幕字体与布局保持原样。打印照片保留自然色，图注在固定宽度内显示。

修改内容后先执行 `bun run check:docs`，旧章节标题契约按预期报 `Missing or reordered content sections`；首次单元测试还识别出上述社交链接测试误改项目 URL 的问题。修订后验证结果：

- `bun run check:static`：类型、lint、生成类型、依赖与文档检查通过。
- `bun run test:coverage`：283 项测试通过；语句、函数、行覆盖率为 100%，分支为 99.46%。
- `bun run check:budgets`：四页构建与资源预算通过。
- `bun run test:http`：5 项 HTTP 测试通过，覆盖四个域名入口的路由、资源和公开内容。
- `bun run test:browser --grep 'resume|portrait keepsake' --update-snapshots=changed`：54 项检查通过，覆盖 Chromium、Firefox、WebKit，两种语言、主题、桌面和移动视口，以及无 JavaScript、打印、无障碍和装饰状态。
- 在本机以 `CI=1` 更新并通过 8 项 Chromium 简历布局检查，刷新 darwin-ci 基线；普通 darwin 的 8 张简历基线也已更新。远程 CI 未运行，不能据此声称已在 GitHub 的 macOS runner 验证。
- 本地 HTTPS 预览在中英文的 1440px、390px 视口均无横向溢出；HTML、Markdown 与 llms.txt 已检查当前团队、项目链接及旧表述移除情况。

最终打印调整后，三种浏览器的打印检查、静态检查和构建预算重新通过。PDFKit 确认中英文各为两页，当前团队、专利和两个项目名称都可从 PDF 正文提取，打印控件没有进入文档；已人工查看打印页面。正文英文单词由约 562 减至 454，中文汉字由约 936 减至 813（不计 frontmatter 和链接地址）。
