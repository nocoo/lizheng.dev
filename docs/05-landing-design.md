# 05 — lizheng.me 掌机落地页设计

状态：新设计规格，尚未实现。内容来源：[英文入口](content/03-landing-en.md)、[中文入口](content/04-landing-zh.md)。旧入口页、样式、背景和动画全部重写。

## 核心画面

首屏是一台可操作的经典竖向掌机，置于有摄影棚照明质感的空间中。它具有真实壳体厚度、嵌入式屏幕、十字键、斜置圆形按键、两枚细长功能键和扬声器开孔。它既是主视觉，也是信息容器和导航控制器。

拟用原创机身标识：ZL / PERSONAL SYSTEM。屏幕内容是 Zheng Li 的真实自我介绍和四个真实入口。产品任何可见文字、元信息、图片中不使用参考品牌名称、标志或现成游戏素材。不要将方案简化成“普通网页外面套一个圆角框”。

## 几何与材质

| 部位 | 规格与视觉意图 |
| --- | --- |
| 壳体 | 宽高约 0.60，直立比例；上部较方，下部右角更大圆角；右侧和底部可感知 12–20px 视觉厚度 |
| 桌面主物体 | 常规宽 390–450px，视可用高度缩放，不能为塞入一屏压小正文 |
| 机壳表面 | 温灰/象牙色微颗粒塑料，细腻倒角、接缝、高光与环境阴影分层 |
| 屏幕框 | 烟灰色凸起边框与内凹暗部，玻璃位于其内部，左侧低调电源指示灯 |
| LCD | 接近 10:9 的屏幕比例；橄榄绿底、四阶深绿图像；清晰文本位于纹理上方 |
| 十字键 | 左下，深色实体按键，圆角很小，顶面与侧面高光分离 |
| A / B | 右下斜置两个圆键，深莓红/酒红，凹刻字标，按下有可见行程 |
| SELECT / START | 下方两个倾斜细长键；功能必须真实，不作无效摆设 |
| 扬声器 | 下右侧斜向窄槽，用几何光影表现，aria-hidden |

物体只允许很克制的初始角度与视差，保持正面文字可读。质感依靠多层几何、渐变、局部纹理和投影，不依赖整张栅格背景图承载 UI，也不将屏幕文字画进 canvas。

Light 为米灰摄影棚环境与象牙壳；Dark 为深灰环境与石墨壳，LCD 保持清晰的绿色视觉。灯光、反射、按钮边缘需要分别定稿，不能用 filter: invert 粗暴变换。

## 屏幕信息架构

默认首页显示真实姓名、头像的四阶点阵版本、职位、两行自我介绍及四个链接入口：Blog / Résumé / GitHub / LinkedIn，对应中文版本完整本地化。可将身份介绍与导航组织成两个相邻屏幕状态；首次进入不要求用户找到隐藏操作才能访问核心链接。

默认 HTML 已包含完整身份信息及四个标准 a 链接。增强后的紧凑屏幕可以切换 PROFILE / LINKS；无 JS 时仍以同一 LCD 视觉容纳可滚动的完整内容，不显示空白或永久启动画面。移动端和文本放大后屏幕允许自然增高，10:9 是设计基准而不是裁切内容的硬锁。

介绍内容不缩写到遗失职位和资历；不能为了像素感把中文做成无法辨认的位图字。底部简短帮助如“方向键选择 · A 打开”来自 UI 文案，不增加人物事实。

## 操作与状态模型

| 输入 | 结果 |
| --- | --- |
| 直接点击/轻触屏幕链接 | 原生链接导航，JS 未就绪也可用 |
| 十字键 / 设备内方向键 | 改变当前选中入口或屏幕分区；焦点与选中状态有明确映射 |
| A / Enter | 打开当前链接；保持原生 Ctrl/Cmd 点击等浏览器语义 |
| B / Escape | 从介绍/帮助返回链接主屏；主屏上不给出虚假的返回导航 |
| SELECT | 切换 PROFILE / LINKS，并明确当前分区 |
| START | 回到主屏 / 结束本次启动展示；不自动打开外链 |
| 语言控件 | en/zh 显式 URL，不藏在游戏式组合按键中 |
| 主题控件 | light/dark 明确切换，使用可识别图标和可访问名称 |

状态至少包含 currentPanel、selectedDestination、bootPresentation、theme、locale、motionPreference。转换在独立 TypeScript ViewModel / reducer 中表达，禁止让 DOM 动画成为业务状态真值。

所有实体按键使用 button；标准链接保留真实 href 和 Tab 次序。只在设备交互区获得焦点且不带修饰键时处理方向键；不截获整个网页的滚动键。不绑定强制游戏手柄、不要求拖动或滑动才能完成导航。

## 字体与图像

- 机身刻字、外部小标题：Space Grotesk，偏紧凑字距，尺寸与塑料刻印质感协调。
- LCD 英文短标题：Silkscreen，控制字号与数量；说明/职位采用 Geist Mono 或清晰的等宽文本。
- LCD 中文：经过人工检查的 Noto Sans SC 子集，像素氛围来自边框、图像和布局，不能牺牲汉字阅读。
- 字体文件本地托管，保留授权文件，按语言拆分。字体失败时 fallback 不改变按钮尺寸和屏幕布局。
- 从原始人像重新制作四阶 dithering 头像，校验眼睛、五官和身份辨识度。适合输出 AVIF/WebP 与无损小图备选。
- 新制微颗粒贴图、独立图标和 OG 画面；记录来源、裁切、压缩和许可证。不得用旧版头像优化脚本、旧背景 SVG 或旧样式拼出新设计。

不预设必须使用图片生成模型。壳体、按键和屏幕优先由新 CSS / SVG 构造，以便保持清晰、可交互和可调整；只有确实改善画面的摄影/纹理素材才引入栅格图。

## 动效编排

| 阶段/交互 | 时间目标 | 设计 |
| --- | --- | --- |
| 首帧 | HTML / CSS 到达即显示 | 壳体轮廓、姓名与入口立即有内容，不依赖 JS 完成 |
| 场景入场 | 0–420ms | 阴影和物体由低位约 10px 缓慢落定，透明度过渡不过黑 |
| LCD 唤醒 | 120–600ms | 轻微亮度收敛与内容淡入，最长约 700ms；用户输入立即结束装饰序列 |
| 屏幕切换 | 120–180ms | 短交叉淡化，焦点稳定，无长位移动画 |
| 按键 | 按下 70–100ms，回弹 120–160ms | 1–2px 行程、阴影缩短，反馈与点击同步 |
| 桌面视差 | 指针活动时 | 最大约 ±2°，细小高光偏移；离开回正 |
| 空闲 | 稳定 | 无永久 RAF 循环，无持续闪烁、滚动扫描线或漂浮物 |

启动演出是装饰，不是假加载进度条、不等待字体/图片/网络请求，也不阻塞链接。普通模式保留完整设计；减少运动模式取消视差和空间位移，使用短淡入或直接显示，壳体材质和屏幕内容完全相同。

动画优先使用 transform / opacity 与 Web Animations API；静态纹理不每帧重绘。视口不可见或页面隐藏时停止更新。音效不自动播放，本期默认无音效，避免为“真实设备”制造意外噪音。

## PC 与移动端

- 宽桌面：主体置于精心构图的光影空间，旁边可有极简姓名/导航说明；避免左右大段介绍与屏幕重复。
- 触控手机：机身最大约 calc(100vw - 32px)，按钮保持至少 44px 命中区；取消指针视差，保留按压反馈。
- 320px 窄屏：屏幕文本仍至少 14–16px，控制区不挤压文字。必要时放宽屏幕高宽比或纵向滚动。
- 手机横屏/低高度桌面：允许整页滚动，绝不全局 overflow:hidden 把按键与页脚裁掉。
- 200% 缩放、动态浏览器工具栏、safe-area 和虚拟键盘变化不造成内容不可达。

## 设计验收

首要人工验收：一眼能认出实体掌机；屏幕像嵌入玻璃后的 LCD；壳体与按键有统一光源和真实行程；点阵头像仍可认人；字体与机身标识像同一件产品。不能用测试通过替代这次视觉评审。

必须提供：桌面和手机各一组 light/dark × en/zh 截图；正常入场与 reduced-motion 录屏；慢网首帧；键盘和触控操作；字体失败/JS 关闭/200% 缩放案例。

性能与 A11y 测试按 [07](07-quality-and-tdd.md) 执行。出现冲突时优先优化实现和细部对比，不撤掉掌机设计，也不在屏幕中塞入面向开发者的解释文字。
